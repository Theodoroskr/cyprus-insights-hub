# Explore Cyprus (TourismHub)

- `tour_listings` are public only when `published` with a source/official link and a last-verified date (RLS); map pins only when `coords_verified`; one listing links to many destinations via `tour_listing_destinations`. Why: only confirmed visitor details, no duplicate pages.
- Every visitor-facing listing/destination text has an `_el` twin shown via `pick()` with English fallback; districts translate via `DISTRICT_EL`; `?lang=el` opens the Greek version and the switch keeps the URL in step. Why: one page per place in both languages, never a blank field.
- Nicosia City & Countryside (`/explore/nicosia-countryside`) and Conference Venues (`/explore/conference-venues`) are filtered views over `tour_listings`; every pin and card opens `/explore/place/:slug`, which switches template by category (villages → linked sections from `tour_listing_links`, events → `tour_event_editions`, venues → `tour_venue_rooms` + quote form). Filters and view live in the URL. Why: one canonical page per place, filters survive map/list switching.
- Event editions are public only when published with a start date, source and last-verified date; `currentEdition()` features the next unfinished one, older ones archive. Why: no unconfirmed dates.
- Venue quotes: recipient comes only from staff-only `tour_venue_contacts` (verified → trigger sets `quote_enabled`), resolved in `submit-venue-quote`; requests/deliveries are admin-read only, one delivery row per request, `request_key` makes retries idempotent; `QUOTE_EMAIL_READY`/`VENUE_QUOTE_EMAIL_READY` stay false until an email sender domain is wired. Why: visitors can't redirect or read enquiries, no duplicate sends.
- Venue owners: claims, corrections, media and upgrade requests live in `venue_*` tables; owners act only on venues listed for them in `venue_representatives` (`is_venue_rep`, RLS), never on `tour_listings` directly. Submissions go to the private `venue-submissions` bucket and are copied to public storage only on admin approval. Upgrades activate only via the `venue_upgrade_prepare` trigger (paid + term end), and display falls back to free once `plan_expires_at` passes (`currentPlanCode`). PDF imports go through `venue_import_rows` (`matchImportRow`/`mergeImport` in `src/lib/venues.ts`), never overwriting `verified_fields`; a venue publishes only when `PUBLISH_REQUIRED` are verified. Why: owners can't edit what they don't own, nothing unapproved is public, and verified data survives re-imports.
